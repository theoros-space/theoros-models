# Numerics

This document defines the integer arithmetic that the int8 flight graph uses.
`src/theoros_models/numerics.py` is the executable form of every definition
here, and theoros-edge implements the same definitions in C99. Golden vectors
generated by this repository are the bit-exact check between the two.

Requirements: MOD-REQ-040 to MOD-REQ-044.

## Integer widths

| Width | Minimum | Maximum |
|---|--:|--:|
| int8 | -128 | 127 |
| int16 | -32768 | 32767 |
| int32 | -2147483648 | 2147483647 |

`saturate(x, n)` clamps an exact integer to the int`n` range.
`saturating_add` and `saturating_sub` compute the exact sum or difference
of two int`n` operands and saturate it. Operands outside their declared width
are an error, never wrapped.

## Rounding modes

Every rounding operation names one of five modes. For an exact rational value
`v` with `f = floor(v)`:

| Mode | Result |
|---|---|
| `half_even` | nearest integer; when `v - f = 1/2`, the even one of `f` and `f + 1` |
| `half_away_from_zero` | nearest integer; ties go to `f + 1` when `v > 0`, else `f` |
| `half_up` | nearest integer; ties go to `f + 1` (toward positive infinity) |
| `toward_zero` | `f` when `v >= 0`, else `ceil(v)` |
| `floor` | `f` |

`round_to_int(x, mode)` applies a mode to a float64 value. Rounding is done on
the magnitude, whose fractional part is exact in binary floating point, so
values one unit in the last place below one half are never mistaken for ties.

`rounding_shift_right(x, s, mode)` applies a mode to the exact quotient
`x / 2^s` for integer `x` and `0 <= s <= 62`. With `q = x >> s` (arithmetic
shift, which floors) and `r = x - (q << s)` in `[0, 2^s)`, the result is `q`
plus one when `r` exceeds `2^(s-1)`, or when `r` equals `2^(s-1)` and the mode's
tie rule rounds up. The shift `s = 0` returns `x`.

## Fixed-point multipliers

A positive real multiplier `M` is stored as a Q31 mantissa `m` and a shift `e`
with

```text
M ~= m * 2^(e - 31),   2^30 <= m <= 2^31 - 1,   -31 <= e <= 30
```

`quantize_multiplier` finds `e` and the fraction `M / 2^e` in `[1/2, 1)` by
`frexp`, then rounds `fraction * 2^31` half away from zero. If the rounding
reaches `2^31`, the mantissa is halved and `e` incremented. The relative
error is at most `2^-31` (MOD-REQ-042). Multipliers below `2^-32` flush to
`m = 0, e = 0`; multipliers from `2^30 - 2^-2` upward are rejected.

## High multiplication

`srdhm(a, b)`, the saturating rounding doubling high multiply of gemmlowp,
takes two int32 values and returns an int32:

```c
int32_t srdhm(int32_t a, int32_t b) {
    if (a == INT32_MIN && b == INT32_MIN) return INT32_MAX;
    int64_t ab = (int64_t)a * (int64_t)b;
    int64_t nudge = ab >= 0 ? (1 << 30) : (1 - (1 << 30));
    return (int32_t)((ab + nudge) / (1ll << 31));  /* C division truncates */
}
```

The result is `a * b / 2^31` rounded to nearest with ties toward positive
infinity for both signs. The truncating division is part of the definition;
an implementation with a floor shift instead of a division differs on
negative products.

## Requantisation

An int32 accumulator `acc` is scaled by a multiplier `(m, e)`:

```text
left  = max(e, 0)
right = max(-e, 0)
x     = saturate(acc * 2^left, 32)
y     = srdhm(x, m)
z     = rounding_shift_right(y, right, half_away_from_zero)
```

`z` is the scaled int32 value (`multiply_by_quantized_multiplier`). The left
shift saturates at int32, which differs from reference implementations that
leave the overflow undefined. The int8 output is

```text
q = clamp(z + zero_point, qmin, qmax)
```

with `-128 <= qmin <= zero_point <= qmax <= 127`. Clipping activations such as
ReLU6 are expressed through `qmin` and `qmax`. Because `srdhm` and the final
shift round separately, `q` can differ from the correctly rounded real value
by one (MOD-REQ-043); the bit-exact contract is the sequence above, not the
real value.

## Affine quantisation

Real values map to int8 codes with a scale `s > 0` and an integer zero point
`z`:

```text
quantize(x)   = clamp(round_half_even(x / s) + z, qmin, qmax)
dequantize(q) = s * (q - z)
```

Scales and zero points are per tensor or per channel along one axis.
Weights use `qmin = -127` and `z = 0`, a symmetric range in which `-w` is
always representable when `w` is. For an input inside the representable
range `[s * (qmin - z), s * (qmax - z)]` the reconstruction error is at most
`s / 2` (MOD-REQ-044); inputs outside saturate to `qmin` or `qmax`.
Quantisation of weights and calibration statistics happens on the ground, so
the float rounding mode here never runs in flight.
